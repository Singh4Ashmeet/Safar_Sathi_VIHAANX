## 15. Execution plan (3 people, about 2.5 days)

The split and the timeline are unchanged; the free stack adds a longer day zero, a ticker task for Dev A and local builds for Dev C.

### 15.1 Roles

| Person | Role | Owns (100%) | Never touches |
| :--- | :--- | :--- | :--- |
| **Dev A** | Backend | API server, database, watchdog and tick endpoint, notifications and SMS gateway integration, public tracking page, relay gateway endpoint, free hosting setup, seed data, server security | App UI code |
| **Dev B** | Frontend | All screens, navigation, theme, i18n, components, accessibility, mesh visualiser UI, UX polish, demo-mode UI | Server code, crypto, native services |
| **Dev C** | Full-stack and integrator | `safety-core` shared package, OpenAPI contract and code generation, local build setup and CI, native services (background tracking, outbox, secure storage, PIN and duress, shake, BLE), relay transports, merge captain, demo director | Screen layout and styling |

**Why this split integrates cleanly:** A and B never depend on each other's code, only on the OpenAPI contract. B and C meet at a small, frozen set of function signatures (15.4). A and C share one pure-TypeScript package (`safety-core`) with golden test vectors, so the app and the server can never disagree about packet formats.

### 15.4 The B ↔ C interface (frozen at W4, stubs committed at W3)

Dev B imports only these from `services/` (Dev C owns the implementation). C commits stub versions returning fake data first, so B is never blocked.

```typescript
// services/tracking.ts
start(tripId: string): Promise<void>;
stop(): Promise<void>;
useTrackingStatus(): { running: boolean; lastFixAt?: number; pendingPoints: number; online: boolean };

// services/sos.ts
trigger(o: { trigger: 'button' | 'shake' | 'prompt_timeout'; tripId?: string }): Promise<{ sosId: string }>;
useSosStatus(sosId: string): {
  status: 'sending' | 'active' | 'acknowledged' | 'resolved' | 'cancelled';
  deliveries: { guardianId: string; channel: string; status: string }[];
  viaRelay: boolean;
};

// services/pin.ts
verify(pin: string): Promise<'cancel' | 'duress' | 'wrong' | 'throttled'>;
set(kind: 'cancel' | 'duress', pin: string): Promise<void>;

// services/relay.ts
setEnabled(on: boolean): Promise<void>;
useRelayStatus(): { enabled: boolean; peers: number; queued: number; uploaded: number; transport: 'sim' | 'beacon' };

// services/risk.ts (wraps safety-core)
useRiskState(): { level: 'safe' | 'warning' | 'danger'; score: number; triggers: string[] };

// services/connectivity.ts (new)
useServerStatus(): { state: 'ok' | 'waking' | 'offline'; since: number };
```

### 15.7 Branching and merge discipline

- **Trunk-based:** short-lived branches `a/...`, `b/...`, `c/...`; PRs under about 300 lines; at least one reviewer from another role.
- **CI gate:** `pnpm typecheck` and `pnpm test` must pass. `main` must always build and run.
- **Merge windows** at W4, W8, W14, W20, W28, W36. Everyone merges, pulls and runs the smoke test together. Hotfix merges are allowed between windows.
- **Commit prefixes:** `api:`, `ui:`, `core:`, `native:`, `contract:` to make history scannable.
- **Feature flags** through `EXPO_PUBLIC_FEATURES` (for example `relay,ride,fakecall,demo`), so half-finished features never break `main`.
